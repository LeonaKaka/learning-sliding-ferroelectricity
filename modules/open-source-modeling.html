Repository-first track

不是读 README。
是重建作者的建模过程。

这一板块逐个进入真实科研代码库：先理解作者面对的 physical question（物理问题），再追 degrees of freedom（自由度）、symmetry（对称性）、free energy（自由能）、parameter provenance（参数来源）、numerical implementation（数值实现）和 validation（验证）。每个仓库学完只做一次轻量的项目桥接；跨仓库综合与系统审计放到后面。

学习路线

顺序不是按“软件最强”排，而是按学习难度和对当前建模问题的帮助排：先看结构清楚的 continuum model（连续模型），再进入铁电相场、无序统计、多尺度和 JAX 工程。

JAX phase-field

等物理架构已经看懂之后，再学 energy / integrator / model / output 如何工程解耦，避免把软件抽象和物理抽象混在一起。

每个仓库统一拆成五层

Level 1

Physical question（物理问题）
作者究竟想解释什么现象？为什么需要这个尺度的模型？

Level 2

Model construction（模型构造）
自由度、序参量、对称性、能量项与动力学为什么这样选。

Level 3

Parameter origin（参数来源）
逐个区分 DFT、实验、文献、拟合、无量纲选择与唯象假设。

Level 4

Numerical implementation（数值实现）
公式 → 文件 → class/function → 输入 → 输出 → 数值结果。

Level 5

Relevance to my project（对我的项目的启发）
第一遍只做短 bridge，不让自己的模型打断对外部项目的完整理解。

After Level 5

Modeling Taste（建模方法论）
作者哪里敢简化、哪里绝不随便简化、怎样让模型不是 numerical toy（数值玩具）。

证据等级不是装饰

这个 Track 比现有页面再多一层“可追溯性”：同一段解释里明确区分代码事实、论文事实、推导和教学解释。

[源码直接支持]可追到 frozen commit 下的具体 file path 和 class/function/symbol。
[论文直接支持]参数、模型或验证结论来自项目明确关联的同行评议论文。
[推导 / 合理物理解释]由已给公式或代码结构推出，但不是作者逐字写出的结论。
[我的项目中的假设 / 尚未验证]涉及自己的滑移铁电模型时，绝不把可能的类比写成已经成立的材料事实。

为什么先一个仓库一个仓库学

第一遍：Repository-first。站在作者视角完整走完“问题 → 模型 → 参数 → 实现 → 验证”，只在结尾做短 bridge。
第二遍：Cross-project synthesis（跨项目综合）。至少完成前四个仓库后，再集中比较 DFT → continuum、disorder construction（无序构造）、parameter provenance 和 Modeling Taste，最后系统回看自己的模型。
